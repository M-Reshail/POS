Part A Audit — What's Broken
Bug 1: RGB stock stored in localStorage (NOT the database)
The entire RGB management panel reads/writes localStorage.getItem('rgbInventory'). This means:

RGB data is lost on browser clear, not synced across devices, invisible to backend
The Create Sale page generates rgb-{brand} virtual IDs for cart items, but there is no backend table tracking actual crate stock — it's purely cosmetic
Fix: Build a real RGBVariety table in the DB with its own API, replacing localStorage.

Bug 2: Stock counts use stale Zustand cache
InventoryPage calls store.fetchInitialData() on mount and uses store.stockBatches. But after a sale (which calls store.fetchInventory()), if the user navigates to Inventory without remounting, they see stale counts.

Fix: Call store.fetchInventory() and store.fetchProducts() directly in InventoryPage's useEffect (not just fetchInitialData) so data is always fresh on mount.

Bug 3: Inventory page images are hardcoded for 7 brands only
BRAND_IMAGES map only covers 7 beverage brands. New products get an emoji fallback.

Fix: Products carry their own imageUrl field. Use that first, fallback to BRAND_IMAGES, then emoji.

Bug 4 & 5: Product form locked to beverages
"Units per Case" (petConversionFactor) dropdown only has beverage bottle sizes
Category dropdown is enum-locked to 4 drink categories
Fix: Remove the field from the UI. Make category a free-text input with smart suggestions.

Image Storage Choice: Local disk (/uploads/products/)
Why not cloud? This is a local LAN POS. Cloud adds cost, API keys, and requires internet. Express static serving is zero-cost and instant.

multer handles multipart/form-data uploads to backend/uploads/products/
Backend serves: app.use('/uploads', express.static('uploads'))
imageUrl stored as /uploads/products/{filename}
Validation: jpeg/png/webp only, max 2 MB
