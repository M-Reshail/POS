# Release Updates — July 17, 2026

This document details the critical bug fixes, schema finalizations, and normalization updates implemented on July 17, 2026, for the Beverage POS system.

---

## 1. Summary of Changes

### A. Sales Page Crash Fix (P0 Priority)
* **Root Cause**: In the backend `product.service.ts`, the mapping functions for product queries overrode the string column `brand` with the complete joined `brandRel` object:
  ```ts
  brand: p.brandRel ?? { id: null, name: p.brand, displayName: p.brand, imageUrl: null }
  ```
  This changed the `Product.brand` type definition on the frontend dynamically from `string` to `Brand` relation object. Since multiple frontend components (including `SalesPage.tsx`, `ReportsPage.tsx`, and `AdminBillsPage.tsx`) render `product.brand` directly inside React brackets (`{product.brand}`), React crashed with:
  > `"Objects are not valid as a React child"`
  
  This also caused React key errors (collapsing keys to `"[object Object]"`).
* **Fix**: Reverted the brand override logic in the backend `product.service.ts` so that `p.brand` remains a pure string from the database column, while the fully structured brand object is served separately via `p.brandRel`. All frontend components reactively resolved their render crashes.

---

### B. Grouping & Alignment Discrepancies (6 Brands vs. 4 Brands)
* **Root Cause**: The Inventory Page groups products into **4 brands** using normalized lowercase names (`p.brandRel?.name`). However, the Sales Page dynamically computed unique brand cards using:
  ```ts
  const uniqueBrands = Array.from(new Set(inventoryProducts.map((p) => p.brand)));
  ```
  Since the database string column `brand` contained casing variations (e.g. `coca cola` vs `Coca Cola` and `sprite` vs `Sprite`), the Sales Page generated **6 brand cards** with split variants, creating duplicate UI flows.
* **Fix**: Updated `SalesPage.tsx` unique brand computations and filter lookups to group by:
  ```ts
  p.brandRel?.displayName ?? p.brand
  ```
  This correctly normalizes and groups casing variations under the 4 official `Brand` models (`Coca Cola`, `Dew`, `Marinda`, `Sprite`), aligning both Sales and Inventory screens.

---

### C. Ghost Products / Deleted Products Reappearing
* **Root Cause**: Manually created duplicate products with 0 stock (`sprite 500ml`, `sprite 1.5l`, `coca cola 2l`, `coca cola 1.5l` with lowercase keys) had their database flag `is_active` set to `true` (likely reset or created during database updates/testing).
* **Fix**: Executed a direct database correction to soft-delete these duplicates (`isActive: false`). Since the backend product lists explicitly filter `where: { isActive: true }`, these products are now fully hidden from both worker and admin catalogs.

---

### D. TypeScript Compilation and Code Quality Cleanup
* **Unused State**: Removed the unused state variable `brandsLoading` and its stale setters from `InventoryPage.tsx`.
* **Typo Fix**: Corrected the `PaymentMethod` type override mismatch inside `SalesPage.tsx` from `'generate_only'` (underscore) to `'generate-only'` (hyphen), aligning it with the globally defined `Bill` type schemas.
